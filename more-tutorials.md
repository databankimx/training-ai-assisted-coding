PowerShell. Every course’s setup script is PowerShell, and you administer GitHub Enterprise from the command line. A short course on the language, the execution policy, winget, and writing scripts that are safe to re-run would cover what the setup scripts already depend on.

Git and GitHub Enterprise workflow. This would cover branches, pull requests, rebasing, and resolving conflicts, along with how the repositories are laid out. Your development rules require source control before delivery, so this is where the rules become day-to-day practice.

SQL. The C# course touches ADO.NET and SQL injection, and the Java and Python courses reach databases too, but none teaches SQL on its own. A standalone course would cover queries, joins, parameterized statements, and transactions.

ASP.NET Core and Web APIs. The C# course covers OnBase and REST, but it doesn’t have a modern web-application track. A course covering routing, dependency injection, authentication, and testing a web API would fill that gap.

Secure coding. Your rules require SonarQube and Snyk scans before delivery. A course on common vulnerability classes, such as injection, cross-site scripting, and dependency risk, and on how the scanners’ findings are triaged, would connect the scanning rules to the code.

Containers and CI/CD. The repositories already use GitHub Actions. A course on writing workflows, building Docker images, and reading pipeline failures would cover the automation around the code.

AI-assisted development. The C# course has a supplement on it, but the policy applies to every language. A cross-language course on using approved tools, reviewing generated code, and writing prompts would apply across the curriculum.
