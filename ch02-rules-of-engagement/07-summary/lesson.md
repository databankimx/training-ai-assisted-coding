## Summary: Rules of Engagement

This chapter turned the company's AI policy into decisions you can make at your desk. Everything is confidential until it has been cleared. A placeholder can make an item shareable, but only if the rest of it is safe. When a case isn't settled, you ask. When something goes wrong, you report it immediately, and you keep the details.

These are the ideas to carry forward:

* **Classify before you paste.** Allowed, allowed after removing details, not allowed, or ask first. The category depends on what the item identifies, not on how harmless it looks.
* **Only Information Security clears data; your belief does not.** Data stays confidential until the Information Security team has explicitly cleared it. Publishing something doesn't clear it, and neither does your view that it's probably fine.
* **Check the account every time.** The company account is the one for company work, and the free tier is for learning on invented data.
* **New tools go through approval first.** Your manager starts it, IT approves it, and a helpdesk ticket records it.
* **Code that leaves the building needs a quote, source control, review, and scans.** AI-assisted code gets exactly the same treatment.
* **Report promptly.** Stop, note what happened, report it, and keep the evidence.

### Check your understanding

*These questions are written for this course.*

```quiz
A colleague wants to paste a list of customer names into an approved AI tool, to help draft a thank-you note. The list has no account numbers. What is the best answer?
◉ Not allowed. Customer names are customer data, and removing the account numbers doesn't change that.
→ Right. The policy treats customer data as confidential, and the note could be written with placeholders instead.
○ Allowed, because the tool is approved and no account numbers are included.
→ Not quite. Approval covers the tool, not every kind of data you might give it.
○ Allowed, because a thank-you note is harmless.
→ Not quite. Harmless-looking work can still carry customer data, and the policy classifies by the data, not by the task.
```

```quiz
You find an AI writing tool that would save your team time. It is not on the approved list. What should you do first?
○ Start using it on a few small tasks, to see whether it is worth the request.
→ Not quite. The policy says not to use a new tool until IT has approved it, and a trial on real work is still use.
○ Tell a colleague, and ask whether they already use it.
→ Not quite. A colleague's use does not approve a tool, and the review still has to happen.
◉ Tell your manager, then open a helpdesk ticket so that IT can start the review.
→ Right. Managers grant access to approved tools, and IT approves the tool, so the request goes to both.
```

```quiz
An AI tool produced a function for a client's project. It passes your tests. Which statement about delivery is correct?
○ The tests passing is enough evidence, so the function can be delivered once the developer has checked it.
→ Not quite. Passing tests is one check. The rules also require review, source control, and the required scans.
◉ Before delivery, the code needs a development quote, source control, an interactive review, and the required scans, the same as any other code.
→ Right. AI-assisted code gets the same review and delivery process as hand-written code.
○ The function can be delivered without review, because the AI produced it and the tests passed.
→ Not quite. AI-generated code needs the same review as hand-written code, and "the AI wrote it" is not an acceptable explanation.
```
